## 0.5 核心哲學

引用 Linus 式實用主義作為策略開發準則：

1. **解決真實問題**：不為理論完美而堆疊條件，每個條件必須有「為什麼」
2. **消除特殊情況**：如果策略充滿 if/else 例外，重新思考數據結構
3. **不破壞既有部位**：風控訊號（停損）不被任何優化擋住
4. **驗證 > 直覺**：所有條件都要能在歷史資料上量化驗證

## 1. 策略定義 (Strategy Hypothesis)

**定義**：明確說明策略的**邊際（Edge）**從哪來，為什麼能持續賺錢。

**該回答的問題：**
- 這個 Edge 的根源是什麼？（行為偏誤、結構性套利、資訊不對稱、流動性溢酬）
- 在什麼市場狀態下有效？（強趨勢、震盪、低波動、高波動）
- 預期持倉週期？（日內、波段、長期）
- 策略容量上限？（資金規模超過 X 億後失效）
- Edge 何時會消失？（套利者進入、市場結構變化、政策變動）

**為什麼重要：**
- 沒有 Hypothesis 的策略 = 曲線擬合的隨機產物
- 若無法解釋為什麼能賺，回測再好也不該上實盤
- 是後續所有驗證的「假設」基礎

**本策略狀態**：⚠️ 部分（v1.md 有提到「結構+法人+籌碼+動能」，但沒明確說邊際在哪）
**補齊方向**：Part 2.1 補完整 Hypothesis

## 2. 標的池 (Universe)

**定義**：定義策略適用的股票範圍與過濾條件。

**該回答的問題：**
- 市場：台股上市 / 上櫃 / 興櫃 / 海外？
- 流動性過濾：日均成交量、日均成交額下限？
- 市值過濾：小型股 / 中型股 / 大型股？
- 產業限制：金融 / ETF / 權證是否排除？
- 動態更新頻率：每月 / 每季重新篩選？

**為什麼重要：**
- 流動性不足 → 滑價爆表，回測再美也是紙上談兵
- 包含已下市股票才能避免**生存者偏誤（Survivorship Bias）**
- 標的池過大 → 容易找出虛假訊號（multiple testing）

**本策略狀態**：❌ 缺失（v1.md 完全未定義）
**補齊方向**：Part 2.2 定義流動性、市值、產業過濾條件

---

## 3. 資料層 (Data Layer)

**定義**：所有策略所需資料的來源、品質、清洗方式。

**該回答的問題：**
- 資料來源（XQ、TEJ、Yahoo、券商 API）？
- 時間頻率（Tick / 分鐘 / 日線）？
- 復權處理（前復權 / 後復權 / 不復權）？
- 公司行動處理（除權息、減資、分割）？
- 缺失值處理（停牌、暫停交易）？
- 未來函數防護（Look-ahead bias）？
- 資料延遲（盤後幾點才有完整法人籌碼）？

**為什麼重要：**
- 不復權 → KD/RSI 計算錯誤
- 未來函數 → 回測美如畫，實盤虧到死
- 資料延遲 → 策略以為今天就能用，實際隔日才有

**本策略狀態**：⚠️ 部分（XQ 提供資料源，但未討論延遲與復權）
**補齊方向**：Part 4.1 詳列資料需求與品質要求

## 4. 特徵工程 (Feature Engineering)

**定義**：把原始資料轉換成策略可用的訊號特徵。

**該回答的問題：**
- 哪些原始欄位？（OHLCV、買賣超、券商分點）
- 哪些衍生特徵？（MA、KD、RSI、自定義指標）
- 標準化方式？（z-score、min-max、ranking）
- 特徵時間對齊？（T 日收盤 vs T+1 開盤）

**為什麼重要：**
- 特徵設計決定模型上限
- 對齊錯誤 = 未來函數

**本策略狀態**：✅ 已有（四層各自的特徵已定義）
**補齊方向**：Part 2.3 整理計分邏輯

---

## 5. 訊號層 (Signal Generation)

**定義**：把特徵組合成可下單的訊號。

**該回答的問題：**
- 單一訊號 vs 多訊號合成？
- 合成方式：加總 / 加權 / 投票 / 邏輯閘？
- 訊號衰減（Signal Decay）：訊號出現後 N 天還有效嗎？
- 訊號頻率：每天可能出現幾次？

**為什麼重要：**
- 訊號頻率過低 → 樣本不足、無法統計驗證
- 訊號頻率過高 → 交易成本吃光獲利
- 衰減考量讓「隔日進場」的合理性可量化

**本策略狀態**：✅ 已有（總分加總 + 狀態機）
**補齊方向**：Part 2.4 量化訊號優先序

---

## 6. 進出場規則 (Entry/Exit Rules)

**定義**：什麼條件下進場、加碼、減碼、出場。

**該回答的問題：**
- 進場觸發條件（精確布林表達式）？
- 進場確認條件（隔日是否需重新確認）？
- 加碼/減碼規則？
- 出場觸發（停利、停損、時間、訊號反轉）？
- 多訊號衝突時的優先序？

**為什麼重要：**
- 進出場規則的「可重現性」是回測的前提
- 模糊規則（「感覺強就進」）無法回測

**本策略狀態**：✅ 已有（七種執行訊號 + 優先序）
**補齊方向**：Part 2.4 重新整理

## 7. 部位管理 (Position Sizing)

**定義**：每筆交易投入多少資金。

**該回答的問題：**
- 固定股數 / 固定金額 / 固定比例 / Kelly / 波動率調整？
- 單筆風險上限（% of account）？
- 部位調整頻率（每次交易 / 每週 / 每月）？

**為什麼重要：**
- **這是長期績效最重要的決定因素之一**
- 同一策略不同 sizing 可能變賺/虧
- 沒有 sizing = 賭博

**本策略狀態**：❌ 缺失（v1.md 完全未討論）
**補齊方向**：Part 3.1 用 Risk-Based Sizing

## 8. 風險管理 (Risk Management)

**定義**：保護資金不被單一事件或連續虧損摧毀。

**該回答的問題：**
- 單筆停損規則？（價格、ATR、時間）
- 移動停損？
- 部位級風控（單檔上限）？
- Portfolio 級風控（總曝險、相關性）？
- 回撤熔斷（DD > X% 暫停）？
- 黑天鵝防護（跳空、暴跌）？

**為什麼重要：**
- 風險管理是**唯一能控制的事**
- 進場可以錯，風控不能錯
- 一次重大虧損可摧毀多年累積

**本策略狀態**：⚠️ 部分（有停損，但缺 Portfolio 層、缺熔斷、缺黑天鵝）
**補齊方向**：Part 3 全面補齊

## 9. 成本模型 (Cost Model)

**定義**：所有交易摩擦成本的量化。

**該回答的問題：**
- 手續費率與折扣？
- 證交稅（賣方 0.3%）？
- 滑價估計？
- 市場衝擊（大單對價格的影響）？
- 借券成本（做空）？
- 利息成本（融資）？

**為什麼重要：**
- 高頻策略中，成本可能吃掉 50%+ 獲利
- 低估成本 = 回測過度樂觀
- 沒有成本濾網 = 進入賠錢交易

**本策略狀態**：✅ 已有（v1.md 已加入成本濾網）
**補齊方向**：Part 2.5 整理，Part 3.4 補貸券/融資（若需要）

## 10. 執行系統 (Execution)

**定義**：訊號 → 實際下單的橋樑。

**該回答的問題：**
- 委託類型（市價 / 限價 / 停損單）？
- 多週期觸發（日線判斷 + 分鐘線執行）？
- 訂單延遲考量？
- 部分成交處理？
- 失敗重試機制？
- 盤前/盤後特殊處理？

**為什麼重要：**
- 訊號好不代表執行好
- 隔日開盤跳空、盤中洗盤是執行層問題
- 不可能用日線訊號當下單指令

**本策略狀態**：⚠️ 部分（v1.md 討論了雙週期，但未整理成可執行流程）
**補齊方向**：Part 2.6 整理雙週期執行架構

## 11. 回測引擎 (Backtest Engine)

**定義**：模擬策略在歷史資料上的表現。

**該回答的問題：**
- 向量化（vectorbt、pandas）vs 事件驅動（backtrader、zipline）？
- Bar resolution（日線 / 分鐘線 / Tick）？
- 撮合邏輯（next bar open / current bar close）？
- T+1 限制（台股當日買進不能賣）？
- 漲跌停限制（10%）？
- 流動性限制（不超過當日成交量 X%）？

**為什麼重要：**
- 撮合邏輯不對 = 全部數字無效
- 沒考慮 T+1 = 策略在台股根本不能跑
- 不考慮流動性 = 大資金時策略失效

**本策略狀態**：❌ 缺失（v1.md 沒提）
**補齊方向**：Part 4 列出回測引擎需具備的能力（不選具體引擎）

## 12. 績效指標 (Performance Metrics)

**定義**：量化策略好壞的標準化指標。

**該回答的問題：**
- 報酬類：CAGR、Total Return、月勝率？
- 風險調整類：Sharpe、Sortino、Calmar？
- 回撤類：Max DD、Avg DD、DD Duration、Recovery Time？
- 交易類：勝率、PF、Expectancy、Avg Win / Loss、最長連虧？
- 分布類：Skewness、Kurtosis（避免胖尾）？

**為什麼重要：**
- 沒有指標 = 沒有比較基準
- 單看 CAGR 會被波動性大的策略騙
- Sharpe < 1 的策略通常不值得做

**本策略狀態**：❌ 缺失
**補齊方向**：Part 4.3 完整列出目標值與紅線

## 13. 統計驗證 (Statistical Validation)

**定義**：用統計方法檢驗績效是否來自運氣。

**該回答的問題：**
- In-Sample vs Out-of-Sample 切分？
- Walk-Forward Analysis（滾動視窗）？
- Monte Carlo（隨機交易順序）？
- Bootstrap（resampling）？
- 顯著性檢定（t-test、p-value）？

**為什麼重要：**
- 一次回測賺錢可能是運氣
- WFA / Monte Carlo 給出機率分布
- 不做統計驗證 = 把賭場當投資

**本策略狀態**：❌ 缺失
**補齊方向**：Part 4.4

---

## 14. 穩健性測試 (Robustness)

**定義**：在參數、市場狀態、執行條件改變時，策略是否仍有效。

**該回答的問題：**
- 參數敏感度（±20% 是否績效崩盤）？
- Regime 分析（多/空/盤整分段表現）？
- 滑價壓力（0.1%/0.3%/0.5% 是否還活）？
- 黑天鵝壓測（2020/03、2022/Q4 表現）？
- 流動性壓測（部位放大是否衝擊績效）？

**為什麼重要：**
- 過擬合的策略對參數極度敏感
- 只在某個 regime 賺錢的策略不可靠
- 滑價敏感的策略上實盤就死

**本策略狀態**：❌ 缺失
**補齊方向**：Part 4.5

---

## 15. 過擬合檢測 (Overfitting Detection)

**定義**：量化策略「事後解釋」的可能性。

**該回答的問題：**
- Probability of Backtest Overfitting (PBO)？
- Deflated Sharpe Ratio（扣除 multiple testing）？
- Combinatorial Symmetric Cross-Validation (CSCV)？
- 條件數量限制？

**為什麼重要：**
- 加越多條件 → IS 表現越好，OOS 越差
- 學術界證實大部分「漂亮回測」都是過擬合
- 沒做檢測 = 自欺欺人

**本策略狀態**：❌ 缺失
**補齊方向**：Part 4.6

---

## 16. 模擬交易 (Paper Trading / Forward Test)

**定義**：用真實市場、虛擬資金，前向驗證策略。

**該回答的問題：**
- 模擬期間長度（最少 3 個月）？
- 訊號重現驗證（線上算的訊號是否與線下一致）？
- 滑價校準（實際滑價 vs 預估滑價）？
- 通過標準？

**為什麼重要：**
- 回測通過 ≠ 實盤能跑
- 真實資料品質、延遲、執行問題只有 paper trading 能暴露
- 直接上實盤 = 拿錢學習

**本策略狀態**：❌ 缺失
**補齊方向**：Part 4.7 流程

---

## 17. 監控告警 (Monitoring)

**定義**：上線後持續監控策略健康度。

**該回答的問題：**
- 策略健康度指標（滾動 30D 勝率、PF、訊號頻率）？
- 資料健康度（資料延遲、欄位缺失）？
- 執行品質（成交價 vs 預期、滑價）？
- 退化偵測（績效偏離歷史 -2σ）？
- 告警通道（Email、Telegram、Slack）？

**為什麼重要：**
- 市場會變，策略會退化
- 早期偵測退化 → 及時停機

# Part 2：四層共振戰法 — 策略本體

## 2.1 策略 Hypothesis（核心假設）

### 2.1.1 邊際（Edge）來源

本策略假設：**台股中小型股的短中期波段，受四種獨立力量同時推動時，會出現高機率的續漲行情。**

| 維度 | Edge 假設 | 行為金融學依據 |
| :--- | :--- | :--- |
| L1 結構 | 突破壓力區 → 賣壓被消化，買盤接手 | 錨定效應、停損掃蕩 |
| L2 法人方向 | 外資+投信同步買 → 資金共識 | 資訊不對稱、跟單效應 |
| L3 籌碼強度 | 主力買盤占有效成交量 > 10% | 籌碼集中度溢酬 |
| L4 技術動能 | 多均線多頭排列 + 動能指標同向 | 趨勢延續性、慣性 |

**為什麼「同時為真」有 Edge？**
- 單一條件勝率約 50–55%（接近隨機）
- 多條件同時為真 → 假設條件彼此**部分獨立**，聯合機率提升
- 例：四個 55% 勝率的獨立訊號合成 → 理論勝率可達 70%+
- **這是核心假設，必須在回測中驗證是否真的成立**

### 2.1.2 適用市場狀態

| Regime | 適用性 | 預期表現 |
| :--- | :---: | :--- |
| 強多頭（大盤年漲 > 15%） | ✅ 最佳 | Sharpe > 1.5 |
| 弱多頭（大盤年漲 0–15%） | ✅ 可用 | Sharpe 0.8–1.5 |
| 震盪（年漲跌 ±5%） | ⚠️ 警戒 | 易出現假突破，PF 可能 < 1.2 |
| 空頭（大盤年跌 > 10%） | ❌ 停用 | 跳空頻繁，停損吃光獲利 |

**判斷規則**：以大盤 20MA 斜率為 regime filter，斜率轉負時降級為「僅持有現有部位、不新增」。

### 2.1.3 預期持倉週期

- **目標持倉**：5–20 個交易日
- **平均持倉**：預估 10 天
- **最長持倉**：不超過 60 天（時間停損）
- **最短持倉**：不少於 2 天（避免當沖、避免假突破洗單）

### 2.1.4 策略容量上限

- **單檔最大部位**：日均量 × 5%（避免市場衝擊）
- **總策略容量**：粗估 NTD 5,000 萬（容納 10–20 檔同時持倉，無顯著滑價）
- **超過容量會發生**：滑價放大、進出場拖慢、實際績效顯著低於回測

### 2.1.5 假設失效情境（Edge Decay）

需密切觀察以下情境，發生時暫停策略：

| 情境 | 監控指標 |
| :--- | :--- |
| 法人籌碼資料延遲增加 | XQ 資料到位時間 > 17:00 |
| 突發政策變動 | 大盤單日跳空 > 3% |
| 市場結構變化（如 T+0 開放） | 法規公告監控 |
| 套利者進入 → Edge 消失 | 月勝率連 3 個月 < 40% |

## 2.3 四層計分系統

### 2.3.1 計分總覽

| 層 | 計分邏輯 | 來源欄位 | 分數區間 |
| :--- | :--- | :--- | :---: |
| L1 結構 | 突破箱頂 / 站上中線 / 中線以下 | SwingHigh/Low(60D) | 0 ~ 2 |
| L2 法人方向 | 外資+投信 同步 / 單邊 / 同步賣 | 法人買賣超 | -1 ~ 2 |
| L3 籌碼強度 | 籌碼強多 / 一日多 / 中性 / 一日空 | 七大法人券商買賣超 / 有效成交量 | -1 ~ 2 |
| L4 技術動能 | 三陽開泰 / 四大金叉 / 中性 / 熄火 | KD/RSI/MACD/MA | -1 ~ 2 |
| **Total** | L1+L2+L3+L4 | — | **-3 ~ 8** |

> **⚠️ v2.1 註記：等權加總是 baseline，待 single-factor IC 測試後改 IC 加權。**
> Grinold-Kahn 框架：`IR = IC × √breadth`，相關因子合成不會線性提升 IR。
> 四層之間實際相關係數未測（法人買 → 籌碼強 → 動能強 → 突破，可能高度相關）。
> 完成 4 個因子 × 多 holding period 的 IC 測試後，依 IC 大小重新分配權重。
> 此前所有合成訊號的勝率估算僅供參考，不可作為實盤依據。

### 2.3.2 L1 結構分

```
箱頂 = SwingHigh(body_high, 60D, 2, 1, 1)
箱底 = SwingLow(body_low, 60D, 2, 1, 1)
箱中 = (箱頂 + 箱底) / 2

if close > 箱頂        → structure_score = 2  (突破)
else if close >= 箱中  → structure_score = 1  (站上中線)
else                   → structure_score = 0  (中線以下)
```

**設計理由**：只看實體 K 棒（去除上下影線），避免日內雜訊。

### 2.3.3 L2 法人方向分

```
foreign_buy = 外資買賣超
trust_buy   = 投信買賣超

if foreign_buy > 0 and trust_buy > 0     → 2  (同步買)
else if foreign_buy > 0 or trust_buy > 0 → 1  (單邊買)
else if foreign_buy < 0 and trust_buy < 0 → -1 (同步賣)
else                                      → 0  (中性)
```

**設計理由**：外資+投信代表台股最有資訊優勢的兩大法人，共識買進是強訊號。

### 2.3.4 L3 籌碼強度分

```
chip_total = 外資 + 投信 + 自營 + 前十大 + 關鍵 + 官股 + 地緣 (七大來源)
net_volume = volume - 現股當沖 - 資券互抵
chip_ratio = chip_total / net_volume

if chip_ratio >= 0.10  → 2  (籌碼強多)
else if chip_ratio > 0 → 1  (一日多)
else if chip_ratio < 0 → -1 (一日空)
else                   → 0  (中性)
```

**設計理由**：絕對買賣超會被股本大小扭曲，**相對比例（占有效成交量）才能跨股比較**。
扣除當沖與資券互抵 → 剩下的才是「留下來的籌碼」。

### 2.3.5 L4 技術動能分

```
# 熄火（優先判斷）
if close < ma5 and k < d and rsi_5 < rsi_10
    → momentum_score = -1

# 三陽開泰：完整多頭結構 + 動能擴張
elif close >= ma5 and ma10 and ma20
     and ema5 >= ema10
     and rsi_5 > rsi_5[1]
     and k > k[1]
     and dif_sl > dif_sl[1]
     and osc_d > osc_d[1]
    → momentum_score = 2

# 四大金叉（KD/RSI/MACD/EMA 同向）或二陽開泰
elif 四大金叉條件 or 二陽開泰條件
    → momentum_score = 1

else
    → momentum_score = 0
```

**設計理由**：MA 看趨勢結構、EMA 看短期動能、KD/RSI 看超買超賣、MACD 看趨勢加速。
四個指標**同向**才給高分，避免單一指標假訊號。

### 2.3.6 Total Score 解讀

| Total | 含義 | 行動 |
| :--- | :--- | :--- |
| 7–8 | 四層全部強多 | 加碼候選 |
| 5–6 | 四層多數共振 | 強多 / 買進候選 |
| 3–4 | 部分共振 | 續抱（已持有）/ 觀察（空手） |
| 1–2 | 多空不明 | 警告 |
| 0 以下 | 偏空 | 熄火 / 出場 |

## 2.4 狀態機與訊號優先序

### 2.4.1 狀態層（四選一，由風險優先序判斷）

```
state_flameout (熄火)：
    momentum_score == -1 OR close < 箱底
    → 風險優先，先判此狀態

state_strong_buy (強多)：
    structure_score >= 1
    AND direction_score >= 1
    AND chip_score >= 1
    AND momentum_score >= 1
    AND (structure_score = 2 OR direction_score = 2
         OR chip_score = 2 OR momentum_score = 2)
    // 等價：四項都 >= 1 且至少一項 = 2
    // v2.0 原寫成 total_score >= 5，化簡為此邏輯（同義但更清晰）

state_hold (續抱)：
    structure_score >= 1
    AND momentum_score >= 1
    AND total_score in [3, 4]

state_warning (警告)：
    total_score <= 2
    AND NOT state_flameout
```

### 2.4.2 執行層（七選一，按優先序）

**優先序：停損 > 賣出 > 停利 > 減碼 > 加碼 > 買進 > 續抱**

| 訊號 | 觸發條件（簡化版，細節見 2.7 程式碼） |
| :--- | :--- |
| signal_stoploss | 已持有 AND (close < 箱底 OR close < 前波低點) |
| signal_exit | 已持有 AND (熄火 OR 連續兩天總分 <= 警告線) |
| signal_takeprofit | 已持有 AND 爆量長上影 AND 總分下降 AND 淨利 >= 1.5% |
| signal_reduce | 已持有 AND 有淨利 AND (強多退回 OR 動能由 2 降至 1) |
| signal_add | 已持有 AND 總分 >= 6 AND 動能=2 AND close > 昨高 AND 已有安全墊 |
| signal_buy | 空手 AND 強多首次成立 AND 結構分=2 AND 通過成本濾網 |
| signal_hold_exec | 已持有 AND 總分 >= 3 AND 動能 >= 1 |

> **🔁 v3 進場重設（M0，ADR-019）：** 上表 `signal_buy` 為 **v2 baseline**（進場過嚴 → IS 無 edge，ADR-017）。**v3 將 `signal_buy` 參數化放寬**為「必含層 + 可選」：`動能≥1 AND 結構≥1 AND (法人方向≥1 OR 籌碼≥1) AND 總分≥5 AND edge_ok AND 非負向 veto`，並搭配 `confirm_days(站穩K日)` / `re-entry cooldown` / `flameout 2-bar 確認` 最小 exit。6 個進場參數的 v2 預設精確重現此 baseline。**完整 hypothesis 與壓測決策見 `docs/superpowers/specs/2026-06-02-m0-v3-entry-redesign-design.md` + ADR-019。** v2 baseline 保留於本表供對照（並存非覆寫）。

## 2.5 摩擦成本濾網

### 2.5.1 成本計算

```
cost_buy_rate  = 手續費 × 折扣 + 滑價 + 回測落差 buffer
                = 0.001425 × 0.6 + 0.001 + 0.002
                = 0.003855  (約 0.39%)

cost_sell_rate = 手續費 × 折扣 + 證交稅 + 滑價 + 回測落差 buffer
                = 0.001425 × 0.6 + 0.003 + 0.001 + 0.002
                = 0.006855  (約 0.69%)

cost_round_rate = cost_buy_rate + cost_sell_rate
                = 0.010710  (約 1.07%)
```

> **⚠️ v2.1 註記：新增 0.2% 回測 vs 實盤落差 buffer。**
> 依 AQR、Two Sigma 公開研究，向量化回測系統低估滑點 **0.1–0.5%**（缺流動性壓力、衝擊成本、部分成交）。
> 取中位數 0.2% 作為買賣雙邊 buffer。小型股實盤可能需上調至 0.5%。
> 此 buffer 為**回測階段必加**，paper trading 後依實測校準。

> **⚠️ code/doc drift 校正（ADR-019 §2.5，2026-06-02）：** 上述 0.2% buffer 為**設計意圖，現行 code 未實作**。實測 `strategy_config.py`（`slip_rate=0.001`、無 buffer）：**`cost_round_rate = 0.671%`、`edge_ok 門檻 = 1.271%`**（非本節文字的 1.07% / 1.3%）。**v0.1 以 code 為單一真相源**；是否把 0.002 buffer 補進 code（→ edge ~1.67%）、及中小型 universe slip 上調至 0.5%，**留 v0.2 換 universe 時拍板**。讀 IS 結果時請以 code 實測值（0.671% / 1.271%）為準。

**Edge Filter（進場前）**：

```
volatility_rate = average(high - low, 14) / close
edge_ok = (volatility_rate >= cost_round_rate + min_edge_rate)
```

含義：股票本身的波動空間要遠大於來回成本，才有交易價值。
預設 `min_edge_rate = 0.6%` → 波動率至少要 1.3% 以上才考慮。

**Profit Filter（停利前）**：

```
estimated_exit_price = close × (1 - cost_sell_rate)
net_profit_rate = estimated_exit_price / entry_cost_price - 1
profit_ok = (net_profit_rate >= tp_min_net_rate)
```

含義：扣掉所有成本後，淨利至少要達到 1.5%（預設）才停利。

### 2.5.3 風控訊號不受成本濾網限制

**停損（signal_stoploss）與賣出（signal_exit）不被成本擋住。**

原因：
- 風控是保命，不能因為「賣會虧成本」就硬撐
- 成本濾網只用於**主動交易決策**（買進、加碼、停利）
- 被動風控訊號**永遠優先**

## 2.6 雙週期執行架構

### 2.6.1 為什麼需要雙週期

日線策略的盲點：
- 訊號要等收盤確認 → 隔日才能下單
- 隔日開盤跳空、盤中洗盤 → 進場點變差
- 上沖下洗 → 訊號對但賺不到錢

**解法**：日線判斷方向，分鐘線執行進出場。

### 2.6.2 三層時間框架

| 層級 | 週期 | 功能 |
| :--- | :--- | :--- |
| 大方向 | 日線 | 四層共振狀態 |
| 執行判斷 | 15 分 | 是否真的轉強 / 轉弱 |
| 精準觸發 | 5 分 | 買進、加碼、停損 |

### 2.6.3 隔日進場三模型

**T 日收盤** → 日線出現強多/買進訊號 → 加入隔日觀察名單
**T+1 盤中** → 用以下三種模型擇一觸發：

#### 模型 A：回測 VWAP 進場（推薦）

```
條件：
- 昨日 daily_buy_candidate = 1
- 今日開盤未跌破昨日收盤 -1%
- 5 分 K 收盤 > VWAP
- 5 分 K 曾回測 VWAP 附近（誤差 < 0.3%）
- 5 分 K 為紅 K（close > open）

適用：強勢股開高震盪，等回測再上車
```

#### 模型 B：Opening Range Breakout

```
條件：
- 昨日 daily_buy_candidate = 1
- 09:00–09:30 形成 OR 區間
- 5 分 K 收盤 > OR 高點
- 5 分 K 成交量 > 過去 20 根 5 分均量

適用：盤中整理後再突破，量價配合
```

#### 模型 C：拉回 EMA20 進場

```
條件：
- 昨日 daily_buy_candidate = 1
- 5 分 K 拉回 EMA20 附近
- 未跌破昨日箱底
- 重新站上 5 分 EMA5

適用：開高拉回到均線支撐
```

### 2.6.4 隔日出場三層級

| 層級 | 觸發時機 | 執行方式 |
| :--- | :--- | :--- |
| 停損 | **盤中即時** | 跌破停損價立刻出，不等收盤 |
| 停利 | **盤中分批** | 爆量長上影 / 達到 2R-3R / 跌破 5 分 VWAP → 先出一半 |
| 賣出 | **收盤確認** | 分數轉弱但未急跌 → 收盤再決定 |

### 2.6.5 不買進場景（嚴格遵守）

當以下任一情境發生，**直接放棄今日進場，等下一次訊號**：

| 情境 | 精確判斷時點 | 判斷規則 |
| :--- | :--- | :--- |
| 開盤跳空 > 3% | **09:00–09:05 第一根 5 分 K close** | `(first_5min_close - prev_close) / prev_close > 0.03` |
| 開盤跌破昨日箱頂 | **09:00–09:05 第一根 5 分 K close** | `first_5min_close < prev_box_upper` |
| 開盤爆量長上影 | **09:00–09:05 第一根 5 分 K** | upper_shadow > body × 1.5 AND volume > 5 日同時段 5min 均量 × 2 |
| 大盤系統性風險 | **09:00–09:05 大盤指數第一根 5 分 K** | `(twse_first_5min_close - twse_prev_close) / twse_prev_close < -0.01` |

> **v2.1 修正**：原本「開盤」未定義時點，導致無法回測。統一改為**第一根 5 分 K close**（即 09:05:00 時點）。
> 若多模型同時觸發，優先序為：系統性風險 > 跳空 > 跌破 > 爆量上影。

# Part 3：風險量化

> v1.md 在風控量化上嚴重不足。本節從交易系統角度建立完整風險框架。
> **核心原則：進場可以錯，風控不能錯。**

## 3.1 單筆風險（Per-Trade Risk）

### 3.1.1 R 單位定義

**R = Risk Unit = 進場價 - 停損價的絕對值**

每筆交易的風險用 R 為單位計量，所有獲利/虧損以 R 倍數表達。

```
範例：
進場價 100 元
停損價 96 元
R = 4 元

若漲到 108 元 → +2R 獲利
若漲到 112 元 → +3R 獲利
若被停損出場 → -1R 虧損
```

### 3.1.2 部位大小公式

**Risk-Based Position Sizing**：每筆交易投入金額由「能虧多少」反推。

```
risk_per_trade = account × risk_pct        // 帳戶風險容忍度
stoploss_distance = entry - stoploss        // 停損距離（絕對值）
position_size = risk_per_trade / stoploss_distance
shares = floor(position_size / entry)       // 取整數張數
```

**完整範例：**

```
account = 1,000,000 元
risk_pct = 0.5%                            // 每筆風險 0.5%（v2.1 從 1% 調降）
risk_per_trade = 5,000 元

進場價 = 100 元
停損價 = 96 元  → 停損距離 = 4 元

position_size = 5,000 / 4 = 1,250 股 = 1.25 張
取 1 張 → 部位 = 100,000 元
最大虧損 = 1,000 股 × 4 元 = 4,000 元 ≈ 0.4% 帳戶
```

> **v2.1 修正**：risk_pct 從 1% 調為 **0.5%**。
> **原因**：v2.0 的 1% × 15 檔上限 = 15% Heat，違反 3.2.1 的 6% 上限。
> **新對齊**：0.5% × 10 檔（新上限）= 5% Heat，在 6% 安全範圍內。
> **代價**：單筆 R 報酬降低，需更高勝率或 R 倍數補償。

### 3.1.3 停損規則優先序

1. **結構停損**：跌破箱底 OR 跌破前波低點（策略本體）
2. **百分比停損**：跌破進場價 -2%（資金管理用，硬上限）
3. **ATR 停損**：進場價 - 2 × ATR(14)（緩衝雜訊）
4. **時間停損**：持倉超過 60 天未達 +1R → 強制出場

**實際停損規則 = 任一觸發即出場（OR 邏輯）**

對應到價位：以 LONG 部位而言，**實際停損價 = max(以上四種停損價)**
（max 是「最高的停損價」= 最先被觸發 = 最嚴格的保護）

> **v2.1 修正**：v2.0 文字「取最寬鬆者避免被洗」與公式 `max` 矛盾。
> 真實意義：max(stop_prices) 是**最嚴格**保護，符合「風控不能錯」哲學。
> 「避免被洗」應靠 3.1.4 的 ATR 緩衝，而非靠放寬停損距離。

### 3.1.4 ATR 緩衝（建議加入）

v1.md 的停損只用 `box_lower` 和 `risk_swing_low`，容易在剛好跌破一點點時被洗。

**改進：**

```
atr14 = ATR(14)
stoploss_with_buffer = max(box_lower, risk_swing_low) - 0.5 × atr14
```

如此停損距離有 ATR 緩衝，不會被「假跌破」騙出場。

## 3.2 Portfolio 級風險

### 3.2.1 Portfolio Heat

**Heat = 所有持倉部位「若全部停損」會造成的總虧損 / 帳戶**

```
heat = Σ(position_i × stoploss_distance_i / entry_i) / account
```

**規則**：Heat ≤ 6%

**含義**：即使所有持倉同時停損，帳戶最多虧 6%。

### 3.2.2 單檔倉位上限

| 限制 | 數值 | 原因 |
| :--- | :---: | :--- |
| 單檔倉位 / 帳戶 | ≤ 20% | 避免單一事件摧毀 |
| 單檔倉位 / 該股日均量 | ≤ 5% | 避免市場衝擊 |
| 同時持倉檔數 | **5–10** | 與 Heat 6% / risk 0.5% 對齊（10 × 0.5% = 5% Heat） |

> **v2.1 修正**：v2.0 寫 5–15 檔，但 15 × 1% risk = 15% Heat，違反 6% 上限。
> 新上限 10 檔對應 5% Heat（仍有 1% buffer 留給未實現損益波動）。

### 3.2.3 相關性限制

| 限制 | 規則 |
| :--- | :--- |
| 同產業最多 | 2 檔 |
| 金融股最多 | 1 檔（與大盤高度相關） |
| 高 Beta 股（Beta > 1.5）最多 | 3 檔 |
| 現金保留 | ≥ 10% |

### 3.2.4 部位調整時機

- 新訊號出現 → 檢查是否突破 Heat / 產業限制
- 若突破 → 拒絕新進場
- 每週五收盤 → Portfolio Review，調整不健康部位

## 3.3 回撤熔斷（Drawdown Circuit Breaker）

### 3.3.1 熔斷層級

| DD 程度 | 行動 | 觸發後 |
| :--- | :--- | :--- |
| **5%** | 觀察 | 記錄、發送警告 |
| **10%** | 減速 | 新進場部位減半 |
| **15%** | 暫停 | 暫停新進場，只管現有部位 |
| **25%** | 全平 | 全部平倉，停機檢討 |

### 3.3.2 月績效熔斷

| 月績效 | 行動 |

## 4.4 統計驗證

### 4.4.1 Walk-Forward Analysis (WFA)

**目的**：驗證策略在「持續移動的時間窗口」中是否穩定。

**設定**：
- 窗口大小：In-Sample 252 天（1 年） + Out-of-Sample 63 天（1 季）
- 滾動方式：每次往前推 63 天
- 總 windows 數：~30 個（10 年資料）

**通過標準**：
- OOS Sharpe > IS Sharpe × 0.6
- OOS 報酬 > 0 的 windows 比例 > 60%
- OOS 平均 MaxDD < IS 平均 MaxDD × 1.5

### 4.4.2 Monte Carlo Simulation

**目的**：用隨機交易順序檢驗績效穩健性。

**方法**：
1. 把所有 trade 的損益記錄抽出
2. 隨機重排 1,000 次
3. 計算每次的權益曲線、MaxDD、CAGR
4. 看 95% 信賴區間

**通過標準**：
- MaxDD 95% 分位 < 35%
- CAGR 5% 分位 > 8%
- 破產機率（DD > 50%）< 1%

### 4.4.3 Bootstrap Resampling

**目的**：估計各指標的信賴區間。

**方法**：bar-level resampling 1,000 次，每次重算 Sharpe / CAGR / MaxDD

**通過標準**：
- Sharpe 95% 信賴區間下界 > 0.5
- CAGR 95% 信賴區間下界 > 8%

### 4.4.4 Deflated Sharpe Ratio (DSR)

**目的**：扣除「測試 N 種策略後挑出最好的」這種 multiple testing 偏誤。

**公式**：[Bailey & López de Prado, 2014]

```
DSR = (Sharpe - E[max Sharpe]) / σ(Sharpe)
```

考慮：
- 測試的策略數 N
- 報酬分布的偏態與峰態
- 樣本長度

**通過標準**：DSR > 0.95（95% 信心水準）

> **⚠️ v2.1 新增：DSR 計算必須記錄 N（測試的策略/參數組合數）。**
>
> **記錄義務**：
> - 所有 grid search 的參數組合數
> - 所有「試過但放棄」的條件變體
> - 所有 holding period / threshold 的測試次數
>
> **若 N 不誠實記錄 → DSR 嚴重高估，等於沒做檢測。**
>
> **建議流程**：
> 1. 開新檔 `experiment_log.md` 從 v2.1 起逐筆記錄
> 2. 每次參數調整、條件嘗試都寫入，含時間戳
> 3. 計算 DSR 時 N = 累計獨立測試數
>
> 從 v1_chatlog 估計，N 已經至少 30+（從各版本程式碼迭代次數推算）。

### 4.4.5 t-Test 顯著性

```
H0：策略平均報酬 = 0（無 Edge）
H1：策略平均報酬 > 0（有 Edge）

t = (mean_return - 0) / (std_return / sqrt(n))
```

**通過標準**：p-value < 0.05

## 4.6 過擬合檢測

### 4.6.1 PBO (Probability of Backtest Overfitting)

**方法**：CSCV (Combinatorial Symmetric Cross-Validation)
1. 把樣本切成 N 個區塊（建議 N=16）
2. 隨機選一半做 IS，一半做 OOS
3. 在 IS 找最佳策略
4. 在 OOS 計算該策略排名
5. 重複 C(16,8) 次
6. PBO = OOS 排名落在後半段的比例

**通過標準**：PBO < **30%**

> **v2.1 修正**：原 50% 等於「比拋硬幣好」= 自我安慰標準。
> 依 López de Prado《Advances in Financial Machine Learning》第 14 章：**PBO < 30%** 才算可接受。
> 嚴格的研究者用 < 20%。30% 是兼顧實用與紀律的妥協。

### 4.6.2 策略複雜度上限

| 複雜度 | 上限 |
| :--- | :---: |
| 布林條件總數 | ≤ 15 |
| 自由參數總數 | ≤ 10 |
| 巢狀深度 | ≤ 3 層 |

**目前策略狀態**：條件約 12 個（接近上限）、參數 13 個（已超）→ **過擬合風險高**

**建議**：
- 砍掉 1–2 個邊際效用低的條件
- 合併相似參數
- 用「分數加總」取代「多重布林判斷」

### 4.6.3 防過擬合紀律

| 規則 | 為什麼 |
| :--- | :--- |
| 不在 OOS 反覆調參數 | 變相 IS |
| 不在事後「補條件」解釋失敗 trade | 後見之明偏誤 |
| 不對單一年度績效調整 | 該年可能是異常 |
| 不在多個指標中挑「最好的那個」報告 | 選擇性報告偏誤 |
| 每次調整都記錄 | 留下審計軌跡 |

## 4.7 Forward Test → Live 流程

### 4.7.1 五階段晉升

| 階段 | 期間 | 通過條件 | 倉位 |
| :--- | :--- | :--- | :---: |
| **1. IS 回測** | 即時 | 所有綠燈指標達標 | — |
| **2. OOS 回測** | 即時 | 維持綠燈，PBO < 50% | — |
| **3. Paper Trading** | 3 個月 | 訊號重現、滑價 < 預估 1.5x | 模擬 |
| **4. 小倉位實盤** | 3 個月 | Sharpe > 0.8、無大 DD | 1/4 |
| **5. 全倉投入** | 持續 | 持續監控 | 1x |

### 4.7.2 各階段細節

#### Paper Trading 階段

- 用 XQ 模擬下單，記錄每筆訊號與假設成交價
- 每日對比：實際開盤價 vs 預估進場價（驗證滑價假設）
- 通過標準：
  - 訊號頻率與回測一致（±20%）
  - 平均滑價 < 預估值的 1.5 倍
  - 模擬 Sharpe > 回測 Sharpe × 0.7

#### 小倉位實盤

- 1/4 倉位試水溫
- 嚴格按照規則執行，不臨時調整
- 記錄所有偏離（為什麼沒按訊號下單）
- 通過標準：
  - 實盤 Sharpe > 0.8
  - 無單日 DD > 5%
  - 連續虧損 < 5 筆

#### 全倉投入

- 通過小倉位 → 逐月加倉至全倉
- 每月評估（見 Part 5）

### 4.7.3 退化處理

任何階段出現以下情況 → 降一級或停機：

| 觸發 | 行動 |
| :--- | :--- |
| 連續 3 個月績效 < 回測平均 -2σ | 降一級 |
| 單月 DD > 15% | 暫停 1 週檢討 |
| 半年內出現未預期的策略行為 | 全面審查 |

## 4.8 回測引擎需具備的能力

雖然不選具體引擎，但回測工具必須支援以下：

### 4.8.1 必要能力

| 能力 | 為什麼 |
| :--- | :--- |
| **撮合在 next bar open** | 訊號當日不能成交（look-ahead 防護） |
| **T+1 限制** | 台股當日買進不能賣 |
| **漲跌停限制** | 漲停買不到、跌停賣不掉 |
| **股數整數化** | 真實下單只能整張 |
| **手續費 / 稅 / 滑價** | 真實成本 |
| **資金部位追蹤** | 現金、持倉、總權益 |
| **公司行動處理** | 除權息調整 |
| **多檔同時持倉** | Portfolio 級回測 |

### 4.8.2 進階能力

| 能力 | 為什麼 |
| :--- | :--- |
| Walk-Forward 自動化 | 4.4.1 |
| Monte Carlo 重排 | 4.4.2 |
| 參數網格搜尋 | 4.5.1 |
| Regime 分段報告 | 4.5.2 |
| 多資產相關性 | 3.2.3 |

### 4.8.3 不可有的「美化」

| 不可有 | 後果 |
| :--- | :--- |
| 用未來資料計算指標 | look-ahead bias |
| 假設可在任意價格成交 | 滑價失真 |
| 忽略流動性 | 大單無法成交 |
| 忽略停牌、警示股 | 高估成交率 |
| 不考慮 T+1 | 台股策略無效 |

# Part 5：監控與運維

## 5.1 策略健康度監控

### 5.1.1 每日指標

| 指標 | 計算 | 警戒 |
| :--- | :--- | :--- |
| 當日訊號數 | count(signals) | < 預期 50% 或 > 預期 200% |
| 當日成交數 | count(executed) | 與訊號數差距 > 30% |
| 當日 P&L | sum(trade_pnl) | < -2% |

| Portfolio Heat | 見 3.2.1 | > 6% |

| 指標 | 警戒（與歷史對比） |
| :--- | :--- |
| 30D 勝率 | < 歷史平均 -2σ |

| 30D Sharpe | < 0.5 |
| 30D 訊號頻率 | 偏離歷史 ±50% |
| 30D 平均持倉天數 | 偏離歷史 ±50% |

## 5.2 資料健康度監控

### 5.2.1 資料延遲監控

| 資料 | 預期到位時間 | 警戒 |
| :--- | :--- | :--- |
| 收盤價 | 13:30 | > 14:00 |
| 法人籌碼 | 17:00 | > 18:00 |
| 券商分點 | 18:00 | > 19:00 |
| 當沖張數 | 17:30 | > 18:30 |

任一資料延遲超過警戒 → 隔日訊號生成暫停，等資料齊全

### 5.2.2 資料完整性檢查

每日收盤後執行：

```
□ OHLCV 完整（無 NaN）
□ 法人籌碼有值（即使是 0 也要有）
□ 券商分點有值
□ 復權因子已更新
□ 標的池檔數正常（無大量消失）
```

任一檢查失敗 → 告警 + 訊號生成暫停

### 5.2.3 異常值偵測

| 異常 | 規則 |
| :--- | :--- |
| 單日漲跌幅 > 10% | 標記，人工確認是否為異常資料 |
| 成交量為 0 | 排除該訊號 |
| 法人買賣超 > 10 萬張 | 標記異常 |
| 股價跳變 > 50%（疑似除權息未處理） | 暫停該股 |

## 5.3 執行品質監控

### 5.3.1 滑價追蹤

每筆成交記錄：
- 預期成交價（訊號當下價）
- 實際成交價
- 滑價 = (實際 - 預期) / 預期

**警戒**：30 日平均滑價 > 預估值 1.5 倍 → 重新校準成本模型

### 5.3.2 成交率

| 指標 | 警戒 |
| :--- | :--- |
| 訊號 → 成交比例 | < 80% |
| 部分成交比例 | > 20% |
| 流動性導致放棄比例 | > 5% |

### 5.3.3 訊號重現驗證

每週對比：
- 線上即時計算的訊號
- 線下用同樣資料重算的訊號

差異 > 5% → 系統 bug，立即排查

## 5.4 退化偵測與處理

### 5.4.1 退化訊號

| 等級 | 觸發 | 行動 |
| :--- | :--- | :--- |
| L1 警告 | 30D 績效 < 歷史平均 -1σ | 加強監控、記錄 |
| L2 黃燈 | 30D 績效 < 歷史平均 -2σ | 倉位降至 50% |
| L3 紅燈 | 60D 績效 < 歷史平均 -2σ | 暫停新進場 |
| L4 停機 | 90D 績效 < 歷史平均 -2σ | 全平倉檢討 |

### 5.4.2 退化原因分析

退化發生時，按以下順序排查：

1. **執行問題**：滑價、漏單、bug
2. **資料問題**：延遲、缺失、錯誤
3. **市場 regime 變化**：用 4.5.2 regime 分析
4. **策略本身失效**：edge 消失

### 5.4.3 策略下架條件

任一情況 → 永久下架：

- PBO 重算 > 70%（已過擬合）
- 連續 2 季 Sharpe < 0
- 連續 6 個月不創新高
- 出現未預期的策略行為無法解釋
